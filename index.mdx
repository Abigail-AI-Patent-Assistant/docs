Abigail gives AI assistants and engineering teams programmatic access to patent
prosecution: office action analysis, response drafting, USPTO forms, examiner
intelligence, and docket management.

The integration path is the **Model Context Protocol**. Point a compatible assistant at
one URL and it gains 58 tools backed by the same system that runs abigail.app.

```
https://mcp.abigail.app/mcp
```

<Note>
  The older REST developer API at `/v1/openclaw/*` was retired on 2026-07-18 and its
  endpoints now return `404`. Its pages remain under the Legacy REST API tab for
  reference only. New integrations use MCP.
</Note>

## Who is this for?

- **AI assistant users** connecting Abigail to ChatGPT, Claude, or Cursor
- **Law firm engineering teams** integrating prosecution AI into existing docketing systems
- **Product teams** building patent workflows on top of an MCP client

## What you get

| Area | Examples |
| --- | --- |
| Docket | Case list, metrics, alerts, add and sync cases |
| Analysis | Parsed claims with amendment markup, rejections, prior art, examiner intelligence |
| Drafting | The six step guided Draft ROA wizard, or unattended generation |
| Forms | USPTO templates, AI autofill, review, final PDF |
| Filing | Filing package assembly and receipt capture, always human filed |

## Quick example

Every request to `/mcp` requires a valid Bearer token, including the protocol
handshake and the tool listing. Without one the server answers `HTTP 401` and a
`WWW-Authenticate` header naming the protected resource metadata document, which
is the signal a compliant client uses to start the OAuth flow automatically. You
sign in once with your Abigail account; the client handles the rest.
